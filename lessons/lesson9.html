Life after launch

Read real conversations

Launch isn't the end. Real people write things your tests never imagined.

So every week, read a sample of real chats and note what went wrong. Group the failures by kind, because one fix often solves a whole kind.

What went wrong in each chat?

Which kind do you fix first?

Fix the biggest problem first

Count each kind of failure over a week. Then weigh each kind by the harm it does.

A failure that's common but mild, where people just ask again, can wait. A rare one that breaks a must-be-right-every-time rule comes first.

One week of failures. Which do you fix first?
Tap a kind.

And once it's fixed, keep it fixed.

Every failure becomes a test

When you find a failure, add that real chat to the eval set before you fix it. The new test fails, then your fix makes it pass, and it can never quietly come back.

Bringing back an old bug by accident is called a regression. A growing eval set is how you prevent them.

Step through one fix
  1. find"MERN course weekend batch?" got "We don't have a MERN course."
  2. testAdd it to the eval set: it must recognise MERN as Full Stack.
  3. runRun the evals: the new test fails. Good: it shows the bug.
  4. fixAdd "also called MERN" to the Full Stack course page the agent searches.
  5. runRun the evals again: the new test passes, and so do all the old ones.
  6. shipRelease the fix, and tell Arjun it's done.

Support at speed

Northstar's staff will message you with problems and requests, often in a shared chat channel. Answer every message within a day, even if the answer is "looking into it".

Then sort by urgency. Deciding what to handle first is called triage, like in a hospital.

Reading someone else's code

Map it before you touch it

Northstar already has some code. Kevin, the IT lead, wrote a small program that saves every WhatsApp enquiry as a row in the lead tracker.

All of a project's code together is its codebase. Before you change someone's codebase, learn its shape: what each file is for, and where things start.

The README file usually says what the project does. Start there, then look at the file names.

Follow one message

The fastest way to understand a codebase is to follow one real thing through it, from the moment it arrives to the moment it's saved.

Here is the path of one enquiry. Each step is a function, a named piece of code that does one job.

Step through one enquiry
  1. webhookreceive(request): WhatsApp sends the message here.
  2. webhookparse(request): pulls out the phone number, name and text.
  3. leadssave_lead(msg): gets the lead ready to save.
  4. leadsnormalize_phone(msg.phone): tidies the phone number.
  5. leadsfind_lead(phone): is this phone number already in the sheet?
  6. sheetsappend_row(…): if not, adds a new row.

So where do the duplicate leads come from?

Reproduce the bug first

In discovery you found the same person saved as two or three leads. The path shows why that matters: a lead counts as new when its tidied phone number isn't found.

Before fixing anything, make the problem happen on purpose. Then you know what "fixed" looks like.

Run Kevin's function on real numbers from the sheet. Each should come out as the same 10 digits.

Run normalize_phone on each number
def normalize_phone(raw): phone = raw.replace(" ", "") # remove spaces if phone.startswith("+91"): phone = phone[3:] # drop the first 3 characters return phone

Can you predict what it does?

✏️ Practice 3.1

Remember:
replace(" ", "") removes spaces only. Dashes and a leading 0 stay.
startswith("+91") then phone[3:] drops the first 3 characters, but only if they are exactly +91.
1. What does normalize_phone("+91 99999 01299") return?
2. What does normalize_phone("0 99999 01300") return?
3. What does normalize_phone("+91-99999-01301") return?

Prove it works

A small piece of code that checks other code gives the right answer is a test. Write one for every number that failed, and keep the ones that already passed.

Run all the tests before and after your change. The new ones should go from failing to passing, and the old ones should still pass.

Explain the change

You don't just change someone's code. You send a pull request: your change plus a short note, which the owner reads and accepts.

A good note says what changed, why, and what could go wrong. Kevin should be able to say yes without asking you anything.

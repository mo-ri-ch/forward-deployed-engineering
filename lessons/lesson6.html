Agents and workflows

From answering to acting

So far the model answers. Booking a counselling call takes more: find free slots, ask which one suits, book it, confirm.

A system that repeats a loop of decide → use a tool → look at the result until the job is done is called an agent.

Step through the agent booking a call
  1. them"I'm Tom, Python course. Can I book a call Saturday morning?"
  2. decideI need free slots. Use find_slots.
  3. resultAnand 10:00 and 11:00, Divya 10:00 and 11:00, Meera 10:00.
  4. reply"Saturday at 10:00 or 11:00?" Tom: "10:00 please."
  5. decideBook it. Use book_call(Anand, Sat 21 Nov 10:00, Tom).
  6. resultBooked.
  7. reply"Done! Anand will see you Saturday at 10:00."

Does everything need an agent?

Workflow or agent?

When the steps are always the same, write them in code, in order. That's a workflow. It's predictable, cheap and easy to test.

Use an agent only when the next step depends on what the person says.

Good FDEs use the simplest thing that works.

Sort each job

An agent also has to remember things.

Remember the conversation

People give details bit by bit, across many messages. The agent keeps what it has learned so far in a small record, and updates it each turn.

That record is the conversation's state. It's also what gets saved to the lead tracker at the end.

Hand over to a person

Some chats need a person: money trouble, grief, refunds, complaints, or when the agent isn't sure. Passing the chat to a person is a handover.

A good handover includes a short note, so the counsellor knows the story and the family doesn't have to repeat it.

What if the agent itself goes wrong?

Stop it going wrong

Tools sometimes fail or time out. An agent that simply tries again can book the same call twice.

An action that's safe to repeat, because doing it twice has the same effect as doing it once, is called idempotent. Make booking idempotent, and cap how many steps one message may take.
